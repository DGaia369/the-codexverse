# Session Close

Use this at the end of every material codeXverse™ work session.

A work session is not complete until the repository has been reviewed and accurately reflects the work that was completed.

---

# Canon Review

Ask:

- Did anything become canon?
- Was anything proposed, narrowed, expanded, amended, superseded, or retired?
- Was provenance established, corrected, or clarified?
- Did any terminology become locked?

→ Update `docs/canon/`

---

# Standards Review

Ask:

- Did voice standards change?
- Did participant-language standards change?
- Did naming conventions change?
- Did AI collaboration standards change?
- Did coding standards change?
- Did documentation standards change?
- Did release standards change?
- Did we establish a new working rule?

→ Update `docs/standards/`

---

# Architecture Review

Ask:

- Did code change?
- Did implementation change?
- Did the database change?
- Did routing change?
- Did email behavior change?
- Did session handling change?
- Did PDF generation change?
- Did participant flow change?
- Did repository architecture change?
- Was the change verified locally?
- Was the change verified live?

→ Update `docs/architecture/`

---

# Excavation Review

Ask:

- Did we uncover a new architectural insight?
- Did we better understand how something came into recognition?
- Did we preserve reasoning that should not be lost?
- Did an excavation mature into architecture or canon?

→ Update `docs/excavations/`

---

# History Review

Ask:

- Did a significant decision occur?
- Did an unresolved question arise?
- Was a contradiction discovered?
- Was a prior decision replaced?
- Did something become superseded?
- Did we resolve an open item?
- Did a new open item appear?
- Does an existing open item require a status update?

→ Update `docs/history/`

---

# Repository Review

Ask:

- Did the repository itself learn something today?
- Does a repository document require updating?
- Does a template require updating?
- Does governance require clarification?
- Does the repository still tell the same story as the work that was completed?

If the answer is **No**, the session is not yet complete.

→ Update the appropriate repository document.

---

# Engineering Review

Before committing:

- Run the build.
- Verify the build succeeds.
- Review `git status`.
- Review the changes to be committed.
- Confirm documentation and implementation agree.
- Commit only after the repository accurately reflects the completed work.

---

# Completion Rule

A session is complete only when:

- constitutional truth is preserved
- implementation reflects constitutional truth
- documentation reflects implementation
- provenance has been preserved
- unresolved items have been recorded
- the repository accurately reflects the work that was completed

The repository remembers so the codeXverse™ never has to begin again.
