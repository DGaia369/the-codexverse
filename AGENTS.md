## Purpose

The codeXverse™ may use specialized agents as the ecosystem expands.

Their detailed identities, permissions, responsibilities, learning boundaries, and adaptation rules are not yet fully defined.

Until that architecture is deliberately recognized and approved, every current and future agent remains subordinate to the governing documents of the codeXverse™.

## Required reading

Before making code, architecture, documentation, or participant-facing changes, every agent must read:

1. `docs/GOVERNANCE.md`
2. every file in `docs/canon/`
3. every file in `docs/standards/`
4. the relevant files in `docs/architecture/`
5. the relevant files in `docs/history/`

## Governing boundary

Agents may:

- read approved repository context
- identify contradictions
- recommend changes
- propose architecture
- surface risks
- request a ruling from Diana Francis

Agents may not:

- create canon
- amend canon
- infer canon from repetition
- treat silence as approval
- redefine participant identity
- rewrite participant-authored truth
- weaken consent
- override locked terminology
- silently resolve conflicts
- expand their own authority

## Conflict protocol

If an agent finds a conflict between canon, standards, architecture, history, or code:

1. stop
2. identify the conflicting files
3. quote the conflicting language
4. preserve the higher governing layer
5. ask Diana Francis for a ruling
6. document the ruling after confirmation

## Future agent architecture

Individual agents, roles, permissions, learning boundaries, and collaboration protocols will be added only after deliberate review and approval.

Until then, this file establishes the boundary every agent must obey.
